# Session & Context Management Guidelines

대화형 AI 세션은 "단기 기억(RAM)"과 같습니다. 세션이 길어질수록 컨텍스트 제한에 도달하여 에이전트의 판단력이 흐려지고 성능이 저하됩니다. 이 문서는 워크스페이스를 무한정 지속 가능하게 운영하기 위한 가이드라인입니다.

## 1. 세션의 역할 분리

**오케스트레이터 세션 (관제탑)**
- **목적**: 작업 스케줄링, 변경 감지, 작업 할당, 상태 모니터링.
- **수명**: 비교적 길게 유지될 수 있으나, 정기적인 스캔 및 짧은 판단만 수행해야 함.
- **금지 사항**: 이 창에서 직접 코드를 깊게 분석하거나, 대량의 파일을 수정하는 긴 작업을 수행하지 마십시오.

**워커 세션 (서브에이전트 / 새 창)**
- **목적**: 단일 목표 수행 (예: "Detect-ActiveWork.ps1 에러 수정", "인코딩 버그 픽스").
- **수명**: 목표 달성 즉시 종료(소멸).
- **실행 방법**: 오케스트레이터가 `invoke_subagent`를 통해 백그라운드로 실행하거나, 사용자가 새 채팅 창(New Chat)을 열어 단기 작업을 지시합니다.

## 2. 세션 교체 (Session Rotation) 시점

다음 증상이 발생하면 현재 세션(대화창)을 닫고 **새 대화(New Chat)**를 시작해야 합니다:
1. **토큰 경고**: UI에 컨텍스트 한도 도달 경고가 뜰 때.
2. **환각 심화**: 에이전트가 이미 해결된 예전 문제를 반복해서 언급할 때.
3. **거대 작업 완료**: 하나의 큰 기능 구현이나 아키텍처 개편이 끝났을 때.

## 3. 영구 기억 장치 (Persistent Brain) 유지

세션을 교체하더라도 에이전트가 과거의 문맥을 잃지 않도록 모든 중요한 상태는 **파일 시스템**에 저장되어야 합니다.

- `config/last_scan_state.json`: 인프라의 현재 상태 스냅샷.
- `config/task_pipeline.json`: 진행 중이거나 완료된 태스크 목록.
- `reports/`: 스캔 및 분석 결과.
- `docs/`: 시스템 아키텍처 및 결정 사항 (ADR).

> 새 대화를 시작할 때 에이전트는 가장 먼저 `projects.txt`, `standing_orders.md`, `task_pipeline.json`을 읽어 이전 문맥을 복원합니다.
