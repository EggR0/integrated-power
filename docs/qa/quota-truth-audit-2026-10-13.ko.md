# 실제 쿼터 해석 및 표시 전수 점검

상태: 수정과 검증 진행 중. 설치된 0.9.22와 이번 수정 소스의 검증을 구분한다.

## 범위와 판단 기준

Antigravity Gemini 및 Claude/GPT 그룹, Codex, Claude 직접 사용량, 외부 공급자,
로컬 실행 상태를 점검한다. 공급자 수집 → 캐시/파일 → 브로커 HTTP/MCP →
공유 계산 → IDE/두 데스크톱 표시 → 알림/프리웜 판단 경로를 포함한다.

- 잔여율, 사용률, 원시 토큰 사용량, 추정 토큰 수, 운영상 제한을 구분한다.
- 공급자가 보고한 값만 실측 쿼터로 표시한다. K×주간 값은 운영상 제한이다.
- 미확인은 0%, 100%, 무제한으로 치환하지 않는다. 실제 0은 보존한다.
- 리셋 시간이 지났다는 사실로 충전 완료를 추론하지 않는다.
- 수집 완료 시간과 원본 측정 시간을 구분한다. 실패가 원본을 최신으로 만들지 않는다.
- 프리웜 요청 접수/프로세스 실행은 원격 타이머와 소비량 확인이 아니다.
- Git 작업 경로의 기존 태스크 범위 및 사용자 데이터를 변경하지 않는다.

충전 알림은 잔여율 전환만 비교하고 원본 관측 시각을 확인하지 않는다.
이번 수정에서는 관측 출처/시각을 전달하고, 그 정보가 없을 때 새 측정이
확인되었다고 주장하지 않는다. 실제 오래된 공급자 알림이 발생했다는
라이브 사례는 확보하지 않았으므로 이 항목은 관측 근거의 제한으로 구분한다.

## 공급자 원본 근거

Codex의 `usedPercent`는 사용률이다. 잔여율은 100에서 사용률을 뺀 값이며,
`windowDurationMins`와 `limitId`는 창/버킷 구분 근거다. 공식 구현은 stale 표시도
구분한다. [OpenAI Codex app-server 계약](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md),
[공식 창 표시 구현](https://github.com/openai/codex/blob/main/codex-rs/tui/src/status/rate_limits.rs).

Anthropic 원본 API의 전체 입력은 `input_tokens + cache_read_input_tokens +
cache_creation_input_tokens`다. 이것은 이미 전체 입력을 담는 저장소 CSV의
`InputTokens`와 의미가 다르다. [Anthropic prompt caching 문서](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).

2026-10-13 읽기 전용 대조에서 Codex 계정 상태의 사용률/창 길이/리셋과 브로커
잔여율이 일치했다. Antigravity 기존 수집기의 원본 fraction/리셋과 브로커도
일치했다. 자격증명 및 계정 식별자는 기록하지 않았다. Antigravity 원본이
100% 창에도 미래 리셋을 반환하므로, 미래 리셋만으로 이미 소비가 시작된
창이라고 판단할 수 없다. 이 API의 공개 안정 계약은 확인되지 않았다.

## 검증 경계

재현 테스트는 기존 quota-core, TokenManager headless, 브로커, dashboard,
prewarm, compact UI 하네스를 재사용한다. 통과 목록과 격리 HTTP/MCP 및
렌더링 결과는 수정 완료 후 기록한다. 원본 서버 오류/지연 자체를 이 제품의
수정으로 제거할 수 있다는 주장은 하지 않는다.

데스크톱 브라우저에서 정상 쿼터 응답 뒤 HTTP 500을 실제로 반환하는 fixture로
RED를 확인했다. 수정 전 DOM은 `100.00% remaining`을 유지했고 세 프리웜
버튼이 활성 상태였다. 기존 18개 좁은 폭 검사에 실패/0% 복구 검사를 더했다.
이 검사는 사용자의 실행 중인 브로커를 사용하지 않는다.

부모의 추가 RED는 공식 API 구조 그대로 `rateLimitsByLimitId.codex` 아래
primary/secondary를 넣고 legacy rateLimits를 다른 버킷으로 구성했다.
잘못된 선택기는 사용률 20/10 대신 legacy 80/60을 선택했다. 단순화된
fixture가 아니라 실제 snapshot 구조와 limitId 차이를 회귀 조건으로 삼는다.
